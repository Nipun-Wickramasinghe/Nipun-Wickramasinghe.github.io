# Nipun Dulantha Wickramasinghe — Academic Website

A responsive academic portfolio built with plain HTML, CSS, and JavaScript. It is designed for GitHub Pages and requires no build tools.

## Preview locally
Open `index.html` in a browser. Internet access is required for the Google Fonts import; the site falls back to system fonts if unavailable.

## Publish at `https://nipun-wickramasinghe.github.io`
1. Sign in to GitHub as **Nipun-Wickramasinghe**.
2. Create a new **public** repository named exactly `Nipun-Wickramasinghe.github.io`.
3. Upload the contents of this folder (not the containing folder) to the repository root. Ensure `index.html`, `style.css`, and `script.js` are at the root.
4. In the repository, open **Settings → Pages**.
5. Under **Build and deployment**, choose **Deploy from a branch**, select `main` and `/ (root)`, then Save.
6. Wait a few minutes and visit `https://nipun-wickramasinghe.github.io`.

## Add your CV PDF
The homepage links to `cv.pdf`. Export your current CV to PDF and upload it to the repository root with the exact filename `cv.pdf`. If you prefer another filename, update the link in `index.html`.

## Before publishing — personal review
- Check the publication statuses and bibliographic details against the final publisher records.
- Add a professional headshot if desired. The current monogram is an intentional placeholder, not a stock portrait.
- Add direct links to public research code repositories when ready. The current GitHub profile shows one public repository, `cov-emulator`, which is a fork; it has not been presented as an original research project here.
- Consider adding Google Scholar, ORCID, and a personal domain after confirming the correct profile URLs.
- Confirm that you are comfortable publishing the university email address.
- The supplied CV contained a mobile number, referee contact details, GPA, and other personal details. Those have intentionally been omitted from the public-facing page; add only what you explicitly want public.

## Update content
Edit `index.html`. The site uses semantic HTML and does not need a package manager, framework, or build step.
